# Hub-and-spoke multi-instance mode for pm2-monitor

This change adds a `MODE=standalone|agent|server` run-mode selector (default `standalone`) and a full agent↔server WebSocket fabric on top of the existing single-process monitor. The agent reuses the local PM2 integration and dials an outbound-only `wss://` link; the server accepts authenticated agent links, keeps isolated per-agent in-memory state in a FleetRegistry, exposes a unified `/api/agents` surface plus a cosmetic alias store, and runs the existing alert engine across the whole fleet with global maintenance. A versioned, zod-validated JSON protocol with correlation-id request/response carries snapshots, deltas, control, and log relay. The diff is ~10k lines across 83 files; `npm run build` and `npm test` (327 tests) are green.

Watch for: nothing blocking. The standalone path is a faithful extraction and byte-for-byte behaviorally unchanged (confirmed); both-ends command validation, throw-safe agent-token comparison, never-throw codec, correlation timeout/duplicate/unknown handling, alias corrupt-tolerance/concurrency, registry isolation + departed-metric prune, unbounded agent backoff, and secret redaction are all present and tested. One NIT on persisted agent-id suffix robustness (possible).

**Verdict**: APPROVED

## High-level view

Mode dispatch is a single switch in `src/index.ts` over `config.MODE`; standalone wiring was lifted verbatim into `src/boot/standalone.ts` and the only observable deltas are additive (`mode` in the startup log and `mode:'standalone'` in `/health`). The zod schema gained the mode cross-field guards (agent needs SERVER_URL+AGENT_TOKEN, server needs a token, TLS cert/key are all-or-nothing, agent WS path cannot collide with `/ws`) and fails fast at startup as before.

The protocol layer is small and defensive: `decode` never throws (bad JSON or schema failure returns a `BAD_MESSAGE` result the caller answers with an `error:frame`), wire shapes are pinned to the internal types by compile-time equality asserts, and the correlation map resolves timeouts/duplicates/unknown/already-settled responses without ever hanging or mismatching a waiter.

Security posture is the strong part. Agent tokens are a separate credential space compared with the same throw-safe `safeEqual` the human auth uses, support a rotation list, and are never logged. Control commands are validated on both ends — the server validates with the shared zod schemas before routing, and the agent re-validates with its own `RequestSchemas` (path existence against the agent disk) before touching PM2. Redaction was extended with the new secret keys and `SERVER_URL`, and the upgrade/handshake paths log only `{ path, agentId, authed }`.

The FleetRegistry keeps each agent's processes/metrics/errors/pending-control/log-rings fully isolated, prunes metric series for processes absent from an authoritative snapshot, retains an entry as offline on disconnect while failing in-flight commands fast with `AGENT_OFFLINE`, and bounds log relay to a 200-line ref-counted ring. The agent connection retries with unbounded capped backoff, never crashes on an unreachable or synchronously-throwing socket, and resets its backoff counter only on `register:ack` so a bad token holds at the 30s cap instead of hot-looping.

Alerts run through the single reused engine over a fleet event bus with composite `agentId/name` keys; a default identity resolver keeps standalone payloads byte-identical, and an orderly agent disconnect emits one cooldown-gated agent-offline alert rather than a storm of per-process crash alerts. The alias store is the only persisted server datum: in-memory source of truth, synchronous update, serialized/coalesced atomic writes, and warn-and-continue on a missing or corrupt file.

### Standalone fidelity (byte-for-byte behavior preserved)

`src/boot/standalone.ts` is a verbatim extraction of the former `bootstrap()` body — same boot order, same deferred-PM2 facade, same digest/shutdown/handler wiring. The only differences are mechanical: `PUBLIC_DIR` resolves `'..','..'` from the new `dist/boot/` location (equivalent target), and the startup log line moved to `index.ts` with an additive `mode` field (confirmed). `/health` gains only `mode:'standalone'` (confirmed additive).

The one place standalone output could have drifted is the alert engine, which now splits a (possibly-composite) key with `bareName()` and prefixes payloads via `resolveAgent`. In standalone the resolver defaults to `identityResolveAgent` → `{ name: key }` with no `agentId`, so the prefix is empty and `title`/`summary` are unchanged; and because `processNameSchema` is `/^[A-Za-z0-9._-]{1,100}$/`, a valid process name can never contain `/`, so `bareName` is a no-op on every standalone key (confirmed). `targetNames`/`ruleTargets` became a documented superset that reduces to the former literal match when keys have no `/`. The 327-test suite including the preserved standalone tests is green.

### Protocol codec and correlation never fail unsafely

`decode` catches JSON parse failures and funnels schema failures into a `BAD_MESSAGE` result rather than throwing, mirroring the WsHub `handleMessage` contract; the gateway and agent both answer a bad frame with an `error:frame` and (pre-auth) close without creating state (confirmed). Wire shapes in `shapes.ts` are pinned to `src/core/types.ts`/`ControlResult` by `AssertEqual` lines, so an interface drift breaks compilation rather than silently diverging on the wire.

`PendingRequests.settle` resolves exactly one pending unsettled cid and returns false for unknown/duplicate/already-settled responses, so a forged or replayed ack can never resolve the wrong waiter; `create` arms an injected-timer timeout that resolves with `AGENT_TIMEOUT` so a request never hangs; `rejectAll` settles everything on disconnect. Duplicate/unknown/timeout are covered in `correlation.test.ts` (confirmed).

### Agent-token auth and both-ends command validation

`agentAuth.validate` compares the presented token against each configured token with the shared throw-safe `safeEqual`, which sha256-normalizes both sides before `timingSafeEqual`, so a missing/empty/wrong-length credential returns false and never throws (confirmed, AC-23/49); an empty token list yields false. `buildAgentAuthConfig` merges `AGENT_TOKENS` (comma list) with `AGENT_TOKEN` and dedupes, enabling rotation (AC-50).

Control validation happens on both ends: the server's `/api/agents` routes validate `:id` (`agentIdSchema`), `:name` (`processNameSchema`), and the create body (`createProcess.safeParse({ body })`) before routing; the agent's `AgentRuntime.handleControlRequest`/`handleCreateRequest` independently re-validate with its own `RequestSchemas` (so script-path existence is checked against the agent's disk and the cluster-default transform is applied) before calling PM2, returning a correlated `VALIDATION` result on failure without touching PM2 (confirmed, AC-17/18/52).

### FleetRegistry isolation, snapshot prune, offline handling

Each `AgentEntry` owns its own process map, `MetricsStore`, `ErrorTracker`, `PendingRequests`, `MonitorEvents` bus, and log rings, so one agent's data or disconnect cannot touch another's (AC-29). `onSnapshot` replaces the process map wholesale and then drops every metric series whose name is absent from the new authoritative snapshot — the ported `MonitorState.onMetricsTick` prune, so a departed process leaves no ghost series (confirmed, NFR-4). `update:metrics` pushes samples with the wire `ts` verbatim and deliberately does not prune (it does not carry the full process set).

`markOffline` is idempotent on an already-offline entry, rejects every in-flight command with `AGENT_OFFLINE` so nothing hangs, clears log subscribers, retains the entry (and its alias) as offline, and emits one `agent:offline`. `routeControl`/`routeCreate` resolve `AGENT_NOT_FOUND`/`AGENT_OFFLINE` without sending anything when the target is unknown or down. Log relay is a bounded 200-line ring, ref-counted so the upstream `log:subscribe`/`unsubscribe` fire on first/last human subscriber.

### Agent connection resilience and TLS

Reconnect uses the shared `backoffDelay` (base 1s, cap 30s, ±20% jitter); the attempt counter resets only on `register:ack`, so a wrong token (socket opens, gets `register:nack AUTH_FAILED`, closes) climbs to and holds at the 30s cap instead of hot-looping (confirmed). A synchronous socket-construction throw is caught and treated as an immediately-dead link that schedules the next retry, so an unreachable or throwing peer never crashes the agent (confirmed, NFR-2/AC-11). All teardown paths funnel through one idempotent `onLinkDead` guarded by `alreadyDead`. The dial passes `rejectUnauthorized: !insecure` through to the real `ws` socket and logs a clearly-marked insecure warning only when `TLS_INSECURE` is on, which defaults off (AC-54/55).

### Server-mode coexistence on one port

WsHub (`/ws`) and AgentGateway (`AGENT_WS_PATH`, default `/agent`) each attach an `upgrade` listener on the shared HTTP(S) server and each returns without destroying the socket when the path isn't theirs, so they coexist; the config refuses `AGENT_WS_PATH === '/ws'` outright (confirmed). The gateway accepts `/agent` unconditionally (no URL secrets), then bounds the only pre-auth surface: only a `register` frame is accepted pre-auth, a non-extendable 5s handshake timer closes an un-registered socket, and a 50-socket pending cap refuses new upgrades with a raw 503 before a WebSocket is constructed. Native TLS is used when both cert and key are set; otherwise plain HTTP behind a reverse proxy.

### Cross-agent alerts and global maintenance

The reused `AlertEngine` is fed by `FleetAlertBridge`, which attaches to each online agent's per-agent bus and re-emits transitions/errors/metrics onto one fleet bus re-keyed to `agentId/name`; `FleetStateHub`/`FleetErrorWindows` dispatch the engine's primitives back to the owning agent's store by splitting on the last `/`. `buildResolveAgent` makes an operator alias win over the agent's `AGENT_NAME` hint for display. A single `GlobalMaintenanceState` holder is read by the engine and toggled by the reused `/api/maintenance` routes, keeping maintenance and cooldown global. On disconnect the bridge fires one cooldown-gated `emitAgentOffline` and suppresses per-process crash alerts for the orderly disconnect (no synthetic errored events) (AC-33).

### Alias store persistence, corruption tolerance, concurrency

The in-memory map is the single source of truth: `set` validates with `aliasSchema` (trimmed 1–100 printable, control chars rejected), updates the map synchronously, then persists. Persistence is serialized and coalesced — one physical write at a time, re-flushing the latest in-memory state when another `set` landed during a write — via write-temp-then-rename, so a slow write cannot clobber a newer value and the file converges to the newest state (confirmed). `load` is tolerant: a missing file starts empty; invalid JSON or schema failure logs a warn and starts empty rather than crashing (AC-39). An unknown agent id is accepted and persisted for pre-seeding (AC-40). A write failure logs a warn and keeps the in-memory value.

### Secret redaction

`REDACTED_KEYS` was extended with `AGENT_TOKEN`, `AGENT_TOKENS`, and `SERVER_URL`; `redactContext` recurses into nested objects to full depth and `redactUrl` rewrites any `token=` query value to `token=***`. The agent connection, gateway, and server request logger reference tokens only by absence (`{ path, agentId, authed }`) and route request URLs through `redactUrl` (confirmed). The documented edge — `redactContext` not recursing into arrays — is a pre-existing property of the logger, unchanged here, and the new call sites do not array-wrap secrets.

### Test coverage

New suites cover mode selection/config guards, agent id generation+persistence+regeneration, backoff bounds, codec round-trip + decode-never-throws, correlation timeout/duplicate/unknown/already-settled, agent-token validation, both-ends control validation, registry routing/offline/isolation/metric-prune, log relay subscribe/unsubscribe, alias CRUD + reload + corrupt-file tolerance + write coalescing, cross-agent alert attribution + agent-offline, redaction, and an in-process agent↔server loopback integration test exercising handshake, routed control round-trip, and log relay (AC-59). 327 tests pass; `tsc` is clean.

Not tested at this layer (acceptable for v1, matches scope): real TLS certificate verification over the wire (covered only via `rejectUnauthorized` wiring + an injected insecure flag) and native-TLS `https.createServer` boot (the cert/key read path is exercised only indirectly).
